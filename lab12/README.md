# ЛР12 — Мобільні телефони

Сторінка працює з PostgreSQL у Supabase через supabase-js 2.119.0. Сервер Node.js та локальна база даних для запуску не потрібні.

Параметри навчального проєкту зберігаються в `config.js`. Для роботи потрібні правильні Project URL, Publishable key та налаштована таблиця `phones` у доступному проєкті Supabase. Без реального підключення неможливо перевірити фактичне збереження записів або завершити лабораторну.

Підключення до навчального проєкту налаштоване. 8 листопада 2026 року у Chrome перевірено реальні SELECT та INSERT, збереження запису після перезавантаження, пошук, сортування, фільтрацію та обробку помилок. Під час перевірки додано Galaxy A55 (Samsung, 256 ГБ); у каталозі стало сім телефонів. Анонімні UPDATE та DELETE відхиляються.

У PDF каталог книг використано як наскрізний навчальний приклад. Індивідуальне завдання в цій папці адаптовано до погодженої теми «Мобільні телефони». Модель, виробник, пам’ять і ціна є змістовими полями таблиці `phones`. Реалізовано всі базові й достатні вимоги та додаткові вимоги високого рівня 10–12 балів.

## Створення навчальної бази

1. Відкрийте https://supabase.com/dashboard і створіть обліковий запис або увійдіть через GitHub.
2. Створіть окремий навчальний проєкт `phones-lab12` у своїй організації. Якщо створюєте організацію вперше, оберіть план Free.
3. Задайте пароль бази даних і збережіть його для себе. Пароль не потрібно вставляти в JavaScript або додавати в репозиторій.
4. Дочекайтеся завершення створення проєкту.
5. Відкрийте SQL Editor, створіть новий запит, скопіюйте весь вміст `schema.sql` та натисніть Run.
6. Відкрийте Table Editor і переконайтеся, що таблиця `phones` містить шість записів.
7. У Connect скопіюйте Project URL і Publishable key. Ключ також доступний у Settings → API Keys. Якщо публічного ключа ще немає, створіть Publishable key.
8. Для іншого проєкту замініть `url` та `publishableKey` у файлі `config.js` його власними значеннями.

Скрипт SQL призначений для окремого навчального проєкту з тестовими даними. Він вмикає RLS, дозволяє анонімне читання та додавання лише моделі, виробника, пам’яті й ціни. Анонімні UPDATE та DELETE не надаються. Повторний запуск не дублює тестові телефони.

У браузері використовується тільки ключ `sb_publishable_…`. Secret key, service_role і пароль бази даних у клієнтський код не додаються. Для цієї навчальної вправи INSERT відкритий відвідувачам; після завершення перевірки його можна вимкнути, відкликавши право INSERT і видаливши політику `phones_public_insert`.

## Публікація та здавання

Завантажте всю папку `lab12` у свій GitHub-репозиторій, включно з `vendor`. Сторінка на GitHub Pages звертається до вашого Supabase-проєкту через інтернет. База даних і записи залишаються в Supabase; SQL-файл у репозиторії є відтворюваною схемою, а не підключеною базою.

Для здавання використовуйте посилання на GitHub Pages із закінченням `/lab12/` і посилання на код, якщо цього вимагає викладач. Проєкт Supabase повинен бути доступний під час перевірки. Доступ до свого облікового запису Supabase або пароль викладачу передавати не потрібно.

Відкривати сторінку рекомендовано через GitHub Pages або Live Server. Класичні скрипти також завантажуються при відкритті `index.html` подвійним кліком у Chrome; для операцій із базою даних завжди потрібні інтернет і реальний Supabase-проєкт.

## Перевірка перед здаванням

- Після відкриття сторінки видно телефони із Supabase: щонайменше шість початкових записів і додані через форму.
- Новий телефон додається через форму й з’являється у Table Editor.
- Після перезавантаження доданий телефон залишається в каталозі.
- Пошук працює за моделлю або виробником.
- Сортування працює за моделлю, ціною, пам’яттю та новизною.
- Фільтр показує телефони вибраного виробника.
- Невідповідний пошуковий запит показує порожній результат.
- Порожня форма, пробіли замість назви та недодатна ціна не надсилаються.
- На час запиту форма й кнопка оновлення блокуються.
- За помилки запиту введені дані зберігаються, на сторінці є повідомлення.
- Перевірка мережевих запитів підтверджує SELECT і INSERT у таблицю `phones`.
